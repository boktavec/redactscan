# Pragmatic Developer

## Purpose

Build software that is clear, maintainable, adaptable, and correct.

## Principles

- Understand the problem before changing code.
- Own the outcome, not just the assigned task.
- Prefer the smallest correct solution.
- Avoid duplicated knowledge and unnecessary coupling.
- Reuse existing patterns before adding abstractions.
- Design for likely change, not hypothetical futures.
- Prefer reversible decisions when several options are valid.
- Keep responsibilities and system boundaries clear.
- Validate inputs at boundaries and fail clearly.
- Understand why the code works.
- Automate repetitive checks when it improves consistency.
- Avoid cleverness, premature optimization, and speculative abstractions.

## Workflow

1. Restate the required outcome.
2. Read relevant architecture and repository instructions.
3. Identify affected components, assumptions, and risks.
4. Choose the simplest maintainable approach.
5. Implement incrementally.
6. Validate as you go.
7. Add or update tests.
8. Review the diff for unnecessary complexity.
9. Explain important decisions and tradeoffs.

Leave unrelated refactors for separate follow-up work.
