title: "Quarantine store: inert, private, content-addressed entries with strictly validated metadata"

## Outcome

`internal/quarantine` keeps suspicious content (decision `review` or `block`) under `~/.redactscan/quarantine/` so that it is never executable, never readable by other local users, never mistaken for a complete entry when half written, and described by metadata that is refused unless it passes strict validation. Story: REDACT-56. Full spec: `docs/features/quarantine-store/spec.md`. ADR: 0005 (written in PR 1).

Concrete example: the watcher (later) or the scan command opens `~/Downloads/tool.zip` with `safefs.OpenRegular`, and the scan says `block`. `store.Put(f, Input{Source: {download, "https://example.com/tool.zip"}, Name: "tool.zip", Decision: Block, Findings: fs})` copies the bytes into `quarantine/3f9a…c1-8d2e4b7a01f3c955/content` (0600, even though the download was 0755), writes `metadata.json` last, and returns the ID. `store.Read(id)` gives back exactly the same record. `store.Read("../../.ssh")` returns `ErrInvalidID` without touching the disk. A `metadata.json` edited to `"decision":"allow"` returns `ErrCorruptMetadata`.

<Callout id="scope-callout" tone="info">

**Non-goals:** CLI commands, listing, release, delete and cleanup (REDACT-57/58); watcher routing and the contents of `incoming/` and `scans/` (REDACT-59/60); a shared `internal/policy.Decision` (REDACT-49); encryption at rest, retention, backup exclusion; cross-process locking of the budget; Windows.

</Callout>

<Callout id="link-decision" tone="decision">

**Content and metadata are placed with `Root.Link`, never `Rename`.** `link` refuses an existing target, so a pre-planted `content` or `metadata.json` is left untouched and the call fails with `ErrEntryExists`. **Verified** with a scratch probe on macOS (go1.27.1) and Linux (`golang:1.27`, go1.27.3): `Root.Link(tmp, "id/content")` works with a two-component in-root target, returns `EEXIST` on an existing name, and returns "path escapes from parent" through an escaping symlink; `Root.Mkdir` on an existing name returns `EEXIST`. The Linux probe ran as root; PR 1 and PR 3 tests pin the same behaviour as a non-root user.

</Callout>

## Metadata v1

<Code
  id="metadata-code"
  filename="quarantine/<id>/metadata.json"
  language="json"
  code={"{\n  \"schema_version\": 1,\n  \"id\": \"<64 hex>-<16 hex>\",\n  \"sha256\": \"<64 hex>\",\n  \"size\": 1234,\n  \"created_at\": \"2026-10-27T10:00:00Z\",\n  \"source\": {\"type\": \"download\", \"uri\": \"https://example.com/tool.zip\"},\n  \"name\": \"tool.zip\",\n  \"decision\": \"block\",\n  \"findings\": [{\n    \"id\": \"script-curl-pipe-sh\", \"severity\": \"high\", \"category\": \"script\",\n    \"title\": \"...\", \"description\": \"...\", \"artifact_id\": \"a-1\",\n    \"file\": \"install.sh\", \"line\": 12, \"evidence\": \"...\",\n    \"metadata\": [{\"key\": \"count\", \"type\": \"int\", \"value\": 3}]\n  }]\n}"}
/>

<Callout id="json-decision" tone="decision">

**Strict decoding uses `encoding/json/v2` (standard library).** **Verified** with a scratch probe on macOS and Linux go1.27: v2 with `RejectUnknownMembers(true)` rejects duplicate members, case-variant member names and trailing data; v1 `encoding/json` silently accepts all three (last duplicate wins, case-insensitive match). Severity is stored by name and decoded by exact match, not `ParseSeverity`. Finding metadata is a typed `{key, type, value}` list so `int`, `int64`, `float64`, `bool` and `string` round-trip exactly, including integers above 2^53.

</Callout>

`Read` refuses with `ErrCorruptMetadata` and returns nothing partial unless: the file is regular, euid-owned, exactly 0600 and at most 4 MiB (the same constant Put checks before writing); decoding is strict; `schema_version` is 1; decision is `review` or `block`; every field is within its bound; `id` equals the directory name and `sha256` equals the ID prefix. `content` must also be regular, euid-owned, exactly 0600 and the recorded size, else `ErrIncomplete`. Name and URI are redactor-checked only at Put, so a redactor rule change never makes old entries unreadable.

## Security constraints for later stories

- REDACT-58 never derives a release path from stored Name or URI, and verifies and copies from the same descriptor (`verifyContent`).
- Name, URI and finding text are untrusted: the CLI escapes them, and MCP marks them as untrusted quoted data. Neither `Read` nor any MCP tool returns content bytes.
- Every Put failure (`ErrStoreFull`, `ErrMetadataTooLarge`, …) is reported as not quarantined or incomplete, never as clean, and callers never clean the store to make room.
- Findings passed to Put come from `scanner.Registry.Run`; any other producer must apply the same redactor checks.
- `quarantine.Decision` moves to, or is mapped from, `internal/policy.Decision` when REDACT-49 lands.

## Accepted risks

<Callout id="risks-callout" tone="risk">

- **Raw content at rest (user-accepted):** unencrypted, included in backups, no retention policy. On darwin `.metadata_never_index` is created best effort; whether current macOS honours it for a non-volume-root folder is **Assumed**, not verified.
- **sha256 in every ID (user-accepted):** anyone who can list the directory can guess low-entropy content offline. Listing requires our uid because of the 0700 mode.
- **Orphan `.tmp-*` files (user-accepted):** a crash can leave raw content in a 0600 temp file. Temp files count against the budget; cleanup is a follow-up issue filed with PR 3.
- **Budget not serialized:** concurrent Puts can overshoot by the number of in-flight entries. The watcher (REDACT-59/60) should serialize.
- **Same-uid attackers and hard links:** out of scope. nlink is not checked, because a failed temp removal legitimately leaves 2.
- **Size defaults** (256 MiB per entry, 4 GiB and 1000 entries per store, 4 MiB metadata) are **Assumed** placeholders, not measured.

</Callout>

## Verification

- `task test` after each step. Before each PR is marked ready, `task verify` must pass: fmt, lint, test, cross, gosec, govulncheck, gitleaks.
- Linux run in every PR as non-root (`--user 1000:1000 -e HOME=/tmp`), plus a separate root run for the ownership tests, with results recorded in the PR.
- Break-the-guard check, then revert. Each change must make a test fail:
  - drop `ValidID`
  - drop `fchmod` on content
  - use `Rename` instead of `Link`
  - skip the owner check
  - repair entry dirs instead of refusing them
  - decode with v1 `encoding/json`
  - drop the Name redactor check
  - skip the pre-marshal size check
- No test touches the real `~/.redactscan`: every test passes a `t.TempDir()` base.
- Reviews: `staff-engineering-reviewer` and `security-reviewer` on each PR.
