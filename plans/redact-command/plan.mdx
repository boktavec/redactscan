## Outcome

`redactscan redact [-summary] [FILE|-]` runs the existing redactor core over a file or stdin and writes the redacted text to stdout. If the redactor refuses (input over 10 MiB, unsupported encoding, verification failure), the command exits 1, writes nothing to stdout, and never echoes input. Story: [REDACT-2](http://localhost:8080/issue/REDACT-2). Full spec: `docs/features/redact-command/spec.md`.

Concrete example: `cat app.log | redactscan redact -summary > shared.log`. If `app.log` holds two different AWS access key IDs, `shared.log` contains `[AWS_ACCESS_KEY_1]` and `[AWS_ACCESS_KEY_2]` and stderr shows `redactscan: redacted AWS_ACCESS_KEY=2`. If the log contains a truncated `ghp_` token, `shared.log` is empty, the exit code is 1 and stderr shows `redactscan: redaction refused: output could not be verified (kind: GITHUB_TOKEN)`.

<Callout id="scope-callout" tone="info">

**Non-goals:** safe file opening (regular files only, no symlinks, FIFOs, devices) is [REDACT-10](http://localhost:8080/issue/REDACT-10); `-o` output files; streaming or multi-file input; config and profiles; `scan`; MCP; stdin TTY detection. Help, README and messages never call the output "safe to share".

</Callout>

<Callout id="messages-decision" tone="decision">

**The CLI owns every message.** It never prints `err.Error()` from the redactor or the OS. Messages are fixed text plus a kind constant or the user's own path quoted with `strconv.Quote`, so the "never echo input" rule does not depend on library error formatting. Exit 1 stays a clean "refused" signal; I/O problems get their own code 3.

</Callout>

## The openInput seam

<Callout id="seam-risk" tone="risk">

**Known gap until REDACT-10.** `openInput(path)` is the only function that touches the filesystem, and in this story it is plain `os.Open`. A symlink is followed, a FIFO with no writer blocks, a device is read, and a directory fails on read (exit 3). REDACT-10 swaps the body for `safefs.OpenRegular` and extends the exit-3 mapping; nothing else changes. The gap is written into the threat model CLI section and the PR.

</Callout>

## Stdlib behavior relied on

- **Verified** (`go doc flag`, Go 1.27.1): one or two dashes are equivalent, so `--summary` works; parsing stops before the first non-flag argument (`-` is a non-flag), so `redact app.log -summary` is two positionals and exits 2; `flag.ErrHelp` is returned for `-h`/`-help`; `ContinueOnError` returns errors instead of exiting.
- **Assumed**: `os.Open` on a directory succeeds on macOS and Linux and the first read fails. The directory test asserts exit 3 only, so either path passes.
- **Assumed**: a write to a closed stdout pipe raises SIGPIPE and the Go runtime exits the process; either way no raw input is written.
