## Outcome

`internal/redactor` gains one pure function, `Redact(input []byte) (Result, error)`. It replaces AWS access key IDs, context-anchored AWS secret access keys, GitHub tokens and PEM/PGP private key blocks with per-call numbered labels such as `[AWS_ACCESS_KEY_1]`. If it cannot vouch for its output, it returns an error and no output. The package uses only the Go standard library, and the CLI, config, scanner, quarantine and streaming work stay out of scope. The full spec lives at `docs/features/redactor-core/spec.md`.

Concrete example: a 2 MB log containing `AWS_KEY_AKIA<16 chars>`, the same key again later, and a truncated RSA private key block (a BEGIN line with no END). The result has `AWS_KEY_[AWS_ACCESS_KEY_1]` twice and `[PRIVATE_KEY_1]` from the BEGIN line to end of input, with `Counts = {AWS_ACCESS_KEY: 1, PRIVATE_KEY: 1}`.

<Callout id="scope-callout" tone="info">

**Non-goals:** JWT, bearer and OAuth tokens; passwords and PII; unanchored AWS secret keys; base64, URL-encoded, compressed, split or obfuscated secrets; UTF-16/32 text (rejected); cross-call pseudonyms and label re-hydration; streaming; zeroising memory. The output reduces accidental disclosure of the covered formats. It is never described as "safe to share".

</Callout>

## Detectors

<Table
  id="detector-table"
  columns={["Label", "Detection", "Notes"]}
  rows={[
    ["AWS_ACCESS_KEY", "(?:AKIA|ASIA)[A-Z0-9]{16}", "No \\b anchors: RE2 treats _ as a word char, so AWS_KEY_AKIA... would be missed. Over-redaction is safe."],
    ["AWS_SECRET_KEY", "aws_secret_access_key-style name, optional quote, separator (= : => :=), optional quote, then [A-Za-z0-9/+]{40} and any trailing base64 chars", "Name is case-insensitive. Only the value is redacted; the name, separator and quotes are kept."],
    ["GITHUB_TOKEN", "gh[pousr]_[A-Za-z0-9]{36,} | github_pat_[A-Za-z0-9_]{22,}", "No upper bound, so no tail fragment survives."],
    ["PRIVATE_KEY", "-----BEGIN (TYPE ){0,4}PRIVATE KEY( BLOCK)?----- ... matching END", "Case-insensitive. RSA, EC, DSA, OPENSSH, ENCRYPTED, PKCS#8, PGP and empty type."]
  ]}
/>

### PEM cursor scan

A single forward cursor keeps the scan linear. It finds a BEGIN, then the next END. If the types match, the block is one span and the cursor jumps past it, so a nested BEGIN is skipped. If no END follows, or the types differ, the span runs to end of input and the scan stops. A second linear pass handles **orphaned END** markers, which come from logs truncated at the top. Each one is redacted from the end of the previous PEM span (or offset 0) through the END marker. The `Proc-Type:`/`DEK-Info:` headers and the body sit inside these spans.

<Callout id="merge-callout" tone="decision">

**Merge and labels.** Overlapping or touching spans are unioned to `[min start, max end)`. The merged kind is the highest priority constituent: `PRIVATE_KEY` > `GITHUB_TOKEN` > `AWS_SECRET_KEY` > `AWS_ACCESS_KEY` > `LABEL_LIKE`. The equality key is (kind, sha256 of the merged bytes). `N` follows only the order of first appearance by merged start offset per kind, never a hash, prefix, length or the AKIA/ASIA type. Labels are per call: the same label in two calls refers to different values.

</Callout>

## Verification (fail closed)

Verification runs on the exact bytes to be returned and is deliberately looser than detection:

<Table
  id="verify-table"
  columns={["Kind reported", "Loose check"]}
  rows={[
    ["AWS_ACCESS_KEY", "(?:AKIA|ASIA)[A-Z0-9]{16} anywhere"],
    ["AWS_SECRET_KEY", "(?i)secret[_-]?access[_-]?key, up to 16 chars, then 40 base64 chars"],
    ["GITHUB_TOKEN", "gh[pousr]_[A-Za-z0-9]{20,} or github_pat_ followed by a token char"],
    ["PRIVATE_KEY", "(?i)-----(BEGIN|END) up to 64 chars PRIVATE KEY, or PRIVATE KEY( BLOCK)?----- anywhere"],
    ["LABEL_LIKE", "Any label-grammar match not at an offset this call emitted"]
  ]}
/>

<Callout id="verify-risk" tone="risk">

**Accepted false-fails.** A truncated `ghp_` token of 20 to 35 chars, or `secret_access_key` text followed by a 40-char base64 run, makes the whole call fail. That is the fail-closed trade-off. The base64 `-----BEGIN` (`LS0tLS1CRUdJTi`) flag is left out because it would also reject inputs that only contain base64 certificates.

</Callout>

## Future CLI constraints (recorded, not built)

- Read through `io.LimitReader(r, MaxInputSize+1)` and never chunk the input.
- Open regular files only, with safe symlink handling.
- Write output only after `Redact` succeeds. Write `-o` via a temp file in the same directory, then rename.
- Help text never says "safe to share".

## Verification and definition of done

- `task test`, `go test -race ./internal/redactor/...`, and `go test -fuzz=FuzzRedact -fuzztime=60s ./internal/redactor` pass.
- `task verify` passes: fmt, golangci-lint, tests, gosec, govulncheck, gitleaks.
- No new `go.mod` dependencies, and no literal secret material in the repo or PR.
- The threat model and ADR 0001 are written.
