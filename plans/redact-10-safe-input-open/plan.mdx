title: "Safe input opening: regular files only, no symlinks, no hangs"
---

## Outcome

`redactscan redact FILE` opens FILE only when it is a regular file reached without any symlink, and refuses everything else with a fixed message and exit 3, before reading a byte. A symlink, a symlinked directory in the path, a file swapped during the open, a FIFO, a device, a socket or a directory can no longer redirect or hang the tool. Story: [REDACT-10](http://localhost:8080/issue/REDACT-10). Full spec: `docs/features/safe-input-open/spec.md`.

Concrete example: a cloned repo contains `logs/app.log`, where `logs` is a symlink to `~/.aws`. `redactscan redact logs/app.log` prints `redactscan: cannot open "logs/app.log": symlink refused`, exits 3 and writes nothing to stdout. `mkfifo pipe; redactscan redact pipe` returns at once with `not a regular file (fifo)` instead of hanging. On macOS, `redactscan redact /tmp/app.log` still works.

<Callout id="scope-callout" tone="info">

**Non-goals:** stdin checks (a pipe on stdin is normal use); Windows (other platforms refuse with `unsupported platform`); `os.Root` confinement or an allow-symlinks flag; hard-link detection; re-checking the current directory for relative paths; `-o` output; directory scanning; quarantine.

</Callout>

<Callout id="errors-decision" tone="decision">

**Errors carry no path, contents or OS text.** `opError.Error()` is a fixed `safefs: <step> failed` and unwraps to the bare `syscall.Errno`, never the `*fs.PathError`, so `errors.Is(fs.ErrNotExist)` still works. The CLI checks reasons in the order shown and still never prints `err.Error()`. Exit codes are unchanged from REDACT-2.

</Callout>

## Full-path protection and macOS system links (PR 2)

Only the parts of the path the user typed are checked. A relative path starts at the current directory, which is not checked again, so running `redact logs/app.log` from a directory under `/tmp` works.

- **macOS:** `os.OpenFile` with `O_NOFOLLOW_ANY` (`0x20000000`). **Verified** in the macOS SDK `sys/fcntl.h` and `golang.org/x/sys/unix` v0.47.0, and defined locally because `syscall` does not export it. **Assumed** and covered by tests: the refusal errno is `ELOOP`, and the current directory is not checked again.
- **macOS allowlist:** a path starting with `/tmp/`, `/var/` or `/etc/` is rewritten to `/private/...` only when, at run time, that entry in `/` is a symlink owned by root whose target is exactly `private/<name>`. Otherwise the path is left alone and refused. The rest of the path is still checked strictly. This keeps `$TMPDIR` and `t.TempDir()` paths under `/var/folders` working.
- **Linux:** open `/` or `.`, then `syscall.Openat` each directory with `O_DIRECTORY|O_NOFOLLOW`, then the file. This uses only the standard library: `openat2` would need `x/sys`. **Assumed** and covered by tests: a symlinked directory fails with `ELOOP`. If Linux returns `ENOTDIR` instead, the open is still refused, and an `Fstatat` check makes the error report the symlink. `/proc/self/...` is refused because `/proc/self` is a symlink.

## Accepted risks

<Callout id="risks-callout" tone="risk">

- **Between the two PRs:** symlinked parent directories are still followed until PR 2 lands. The threat model says so.
- **Hard links:** a hard link to a sensitive file is a regular file, so it opens. Creating one already needs access to the target, on the same filesystem.
- **Changes after open:** the file's contents can change after it is opened. The 10 MiB read limit still applies.
- **Network and FUSE filesystems:** a regular file there can block on read.
- **Search-only directories on Linux:** a directory with execute but no read permission is refused (fails closed).
- **Platforms:** macOS and Linux only.

</Callout>
