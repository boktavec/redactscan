title: "HashScanner and FileTypeScanner: streaming SHA-256 and real file types from bytes"
---

## Outcome

`redactscan scan FILE` reports the file's SHA-256 and its real type detected from magic bytes, and flags extension spoofing, an executable bit on non-executable content, and deceptive names such as `report.pdf.exe`. Files up to 1 GiB are hashed in 64 KiB chunks and never read whole into memory. These are the first production scanners, so a scan of an ordinary file becomes complete (exit 0). Story: [REDACT-37](http://localhost:8080/issue/REDACT-37). Full spec: `docs/features/hash-filetype-scanners/spec.md`. Decision record to write: `docs/adr/0007` (bounded ReaderAt contract and 1 GiB cap; supersedes ADR 0004 decisions 1-3). Every `security-reviewer` requirement (R1-R10) is included.

Concrete example: an ELF binary renamed to `invoice.pdf` with `chmod +x`.

<Callout id="scope-callout" tone="info">

**In scope:** the `io.ReaderAt` scanner contract with an opaque bounded wrapper; a 1 GiB cap; `Artifact.Mode`; change detection during the scan in the CLI; a new `internal/scanner/builtin` package with `hash` and `filetype`; the findings `hash.sha256`, `filetype.detected`, `filetype.mismatch`, `filetype.executable_bit` and `filetype.deceptive_name`; `internal/textsafe` shared with the report. **Non-goals:** a `MaxInMemoryRead` helper (follow-up), filling `Artifact.SHA256`, archive or binary parsing, polyglot detection, `scan ./dir`, deadlines and SIGINT handling (REDACT-39), a findings exit code (REDACT-50), MIME detection for text and images.

</Callout>

## Findings

<Table
  id="findings-table"
  columns={["ID", "When", "Severity", "Metadata"]}
  rows={[
    ["hash.sha256", "Always", "info", "sha256 (64 lowercase hex), size (int64)"],
    ["filetype.detected", "Always", "info", "detected_type, executable_bit (bool)"],
    ["filetype.mismatch", "Claim from the extension table does not accept the detected type; unknown extension on ELF/Mach-O/PE; no extension on PE", "high for elf/macho/pe, else medium", "claimed_type, detected_type, extension (table constant)"],
    ["filetype.executable_bit", "Executable bit set on zip, gzip or unknown content", "low", "detected_type"],
    ["filetype.deceptive_name", "Name has a dangerous rune or invalid UTF-8, or a document extension before an executable one", "high for elf/macho/pe, else medium", "invisible_rune, double_extension, detected_type"]
  ]}
/>

Detection, first match wins and every check is length-checked first: ELF `7F 45 4C 46`; Mach-O thin (four magics) and fat `CAFEBABE`/`CAFEBABF` only with `1 <= nfat < 45`, so Java class files are not matched; PE needs `MZ`, `e_lfanew` read as a little-endian uint32 into an int64, `>= 0x40` and `+4 <= min(size, 4096)`, then `PE\0\0` from one extra 4-byte read; ZIP `PK\x03\x04`, `PK\x05\x06`, `PK\x07\x08`; gzip `1F 8B 08`; script `#!`. The ELF, Mach-O, gzip, ZIP and PE constants are **Verified** against go1.27.2 stdlib sources. The byte-swapped Mach-O forms, fat64 and the `nfat < 45` rule are **Assumed**.

## Risks and residual risks

<Callout id="risk-callout" tone="risk">

- An in-place rewrite that keeps size, mtime and ctime is undetectable; the hash describes the bytes as read, so quarantine and policy must re-hash their own copy.
- The executable bit is not the same as executable (ACLs, `noexec`, FAT/SMB); findings say "executable bit set".
- Offset-0 magic misses polyglots and appended ZIPs; `MZ` without a PE signature is `unknown`.
- Network or FUSE reads can block: there is no per-scanner timeout and no SIGINT handling (REDACT-39).
- A secret-shaped path makes the registry drop every finding, so the scan is incomplete (fail closed).

</Callout>
