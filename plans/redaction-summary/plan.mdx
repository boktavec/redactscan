---
title: "Redaction summary on stderr: counts by kind, never values"
---

## Outcome

Every successful `redactscan redact` run reports how many items of each kind were redacted, on stderr only, so stdout stays pipeable. Values, labels, offsets and paths never appear in the summary. `-json` gives scripts one counts-only object. `-quiet` silences all success output. Story: [REDACT-13](http://localhost:8080/issue/REDACT-13). Full spec: `docs/features/redaction-summary/spec.md`.

/>

<Callout id="breaking-callout" tone="warning">

**Breaking change (accepted by the user).** Today the summary is opt-in through `-summary`, and stream-mode stderr is empty on success. After this change the summary is on by default, so scripts that expect an empty stderr or use `2>&1` see one more line. Use `-quiet` for the old behavior. Stdout does not change in any mode. `-summary` is still accepted and does nothing.

</Callout>

<Callout id="scope-callout" tone="info">

**Non-goals:**

- offsets, values, labels or the output path in any summary
- JSON error messages (errors stay plain constant text)
- a `"version"` field in the JSON
- any change to `Result.Counts` or to the text summary format

</Callout>

`redactscan: temporary file may remain` is never suppressed. When `WriteSibling` reports `tempLeft` it is always the last line, so under `-json` the JSON object is always the first line.

## Decisions

<Table
  id="decisions-table"
  columns={["Decision", "Why", "Rejected"]}
  rows={[
    ["Summary on by default; -quiet turns it off", "One rule for both modes; matches the story; stdout is never touched", "Opt-in -summary; on by default in file mode only"],
    ["-quiet hides summary, wrote and note", "Unix -q: success is silent; warnings and errors still print", "Hide only the summary; keep the note"],
    ["-json prints counts only, nothing else", "One object to parse; no filename escaping; never values", "JSON plus text lines; include the output path"],
    ["-quiet -json is a usage error", "The flags conflict, so refuse instead of guessing (fail closed)", "Quiet wins; JSON wins"],
    ["JSON keys are exactly Result.Counts, incl. LABEL_LIKE", "Meets the 'matches Counts exactly' criterion with no CLI-side mapping", "Separate label_like field"]
  ]}
/>

## Design

All changes are in `internal/cli`. `runRedact` parses `-quiet`, `-json` and the no-op `-summary`, then rejects the conflict before reading any input. It chooses a summary mode (text, JSON or none) and passes it to the stream path and to `writeCleaned`. A new `printSummary` reuses the existing text formatter. For JSON it marshals `struct{ Counts map[redactor.Kind]int }` with a nil map replaced by `{}`. The summary is printed only after output has been fully written, which is the existing ordering.

**Verified** (`go doc encoding/json Marshal`, Go 1.27.2): string-keyed maps encode with sorted keys and compact output, so the JSON is deterministic.

<Callout id="risks-callout" tone="risk">

**Risks:**

- Scripts that expect an empty stderr break. This is an accepted breaking change, and `-quiet` restores the old behavior.
- A failure to write stderr is ignored and the exit code stays 0, because the output has already been written.
- Under `-json`, a successful write that leaves a temp file adds a text warning line after the JSON. This is documented.

</Callout>
