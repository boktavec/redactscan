---
title: "Redactor kind selection: redact or refuse, never pass through"
---

## Outcome

A profile author can choose which secret kinds `internal/redactor` redacts. For each covered kind, the choice is binary: **selected** kinds are redacted to labels as today, and input containing an **unselected** kind is **refused** as a whole. Selection never reduces detection or verification, and on success the output is byte-identical to `Redact`. Story: REDACT-16. Full spec: `docs/features/redactor-kinds/spec.md`.

  filename="example.go"

  code={"res, err := redactor.RedactWith(input, redactor.Options{\n\tKinds: []redactor.Kind{redactor.KindAWSAccessKey, redactor.KindAWSSecretKey, redactor.KindGitHubToken},\n})\n// input with a PEM private key   -> *VerificationError{Kind: PRIVATE_KEY}, zero Result\n// input with only a GitHub token -> success, Output == Redact(input).Output\n// Kinds: []Kind{\"LABEL_LIKE\"}     -> ErrUnknownKind (checked before size/encoding)\n"}
/>

<Callout id="scope-callout" tone="info">

**Non-goals:**

- passing an unselected kind through, or relaxing the verifier for it
- a distinct "kind not selected" error (security R6, follow-up)
- profiles, config files, CLI flags or MCP exposure of selection
- exported kind lists, a `ParseKind` helper, or new detectors

</Callout>

## Design

`Redact(input)` becomes `RedactWith(input, Options{})`. Nil or empty `Kinds` means all four secret kinds. `RedactWith` first validates the options and copies them into a fixed four-entry set. It then runs the existing size and encoding checks and the full, unchanged `detect()`. Next, it checks the **raw** spans for any unselected secret kind, **before** `mergeSpans`, which overwrites its slice and hides nested kinds. Only then do the unchanged merge, render and verify steps run.

<Callout id="nested-callout" tone="risk">

**Why the check runs on raw spans.** A `ghp_` token whose tail contains `AKIA` + 16 characters matches two detectors. Filtering unselected spans before render would emit `ghp_[AWS_ACCESS_KEY_1]...`. That is below the verifier's GitHub threshold, so part of a real token would leak silently. Rejecting any unselected raw span closes this. The cost is one accepted false failure: with `Kinds=[PRIVATE_KEY]`, a PEM body containing an `AKIA` run is refused as `AWS_ACCESS_KEY`.

</Callout>

## Decisions

<Table
  id="decisions-table"
  columns={["Decision", "Why", "Rejected"]}
  rows={[
    ["Unselected means refuse; the verifier is never relaxed (user)", "Selection cannot weaken the safety net (ADR 0001, fail-closed)", "Pass-through with the verifier skipping the kind; selection only for future non-secret kinds"],
    ["Nil or empty Kinds means all kinds (user)", "The safe zero value; Redact is RedactWith(x, Options{})", "An error for empty Kinds; 'no kinds' meaning refuse-everything"],
    ["Reject on raw spans before merge (user, security R2)", "Closes nested-span and fragment leaks with one total rule", "Filtering before merge (leaks); tracking constituents through merge (complex)"],
    ["Reuse VerificationError{Kind} (user)", "No new CLI path; a distinct error waits for profiles", "ErrKindNotSelected now (R6, follow-up)"],
    ["Constant ErrUnknownKind, validated first", "Deterministic config errors; never echo config or input", "Echoing the bad name; checking input first"]
  ]}
/>
