---
title: "Cleaned file output: write <name>_cleaned<ext> next to the input, atomically and without clobbering"
---

## Outcome

`redactscan redact FILE` writes the redacted result to `<name>_cleaned<ext>` in the same directory as FILE, with mode 0600. The file appears only after redaction succeeds, through a fully written and fsynced temp file that is atomically linked into place (no clobber) or renamed into place (`-force`). A failure never leaves partial or raw output or a temp file, and concurrent runs never produce a mixed file. Story: [REDACT-11](http://localhost:8080/issue/REDACT-11). Full spec: `docs/features/cleaned-file-output/spec.md`.

Concrete example:

- `redactscan redact logs/app.log` creates `logs/app_cleaned.log` and prints `redactscan: wrote "logs/app_cleaned.log"` and `redactscan: note: output may still contain uncovered secret formats` on stderr.
- Running it again exits 3 with `already exists (use -force to replace)`.
- `redact -force logs/app.log` replaces the file atomically.
- `redact -stdout logs/app.log | less` keeps today's behavior, and stdin input still goes to stdout.

<Callout id="breaking-callout" tone="warning">

**Breaking change (accepted by the user).** `redact FILE` used to print to stdout. Now it writes a file, and stdout is empty with exit 0, so `redact f | cmd` and `redact f > out` silently get nothing. Use `-stdout` for the old behavior. ADR 0003 records the decision, and the release notes call it out.

</Callout>

<Callout id="scope-callout" tone="info">

**Non-goals:**

- `-o PATH`
- signal handling to remove temp files
- `golang.org/x/sys`, `renameat2` or `openat2`
- `.gitignore` checks or `git check-ignore` (never shell out)
- Windows
- detecting inputs that are already `_cleaned`

</Callout>

## Why the guarantees hold

<Table
  id="guarantees-table"
  columns={["Threat", "Guarantee"]}
  rows={[
    ["Partial or raw output", "Nothing is created before Redact succeeds; the destination appears only through an atomic link or rename of a fully written, fsynced file."],
    ["Concurrent runs", "Each run has its own O_EXCL temp file. link is atomic no-clobber (exactly one run wins); rename is atomic replace (last one wins, with a whole file)."],
    ["Symlink at the destination", "Refused by the pre-check. If swapped in later, link gives EEXIST and rename replaces the link itself; the target is never written."],
    ["Directory, FIFO or device at the destination", "rename over a directory fails; a FIFO or device entry is only replaced, never opened."],
    ["Symlinked parent directory in content", "Refused by the REDACT-10 input open and by the no-follow directory open."],
    ["Parent directory swapped mid-run", "The root is pinned to a verified directory descriptor and bound to the input's inode; a detected swap gives ErrChanged, and an undetected one still lands in the original directory."],
    ["Umask or inherited mode", "0600 at create time plus f.Chmod(0600) on the descriptor. Inherited ACLs are an accepted risk."]
  ]}
/>

<Callout id="root-decision" tone="decision">

**Why `os.Root` here, when ADR 0002 rejected it.** ADR 0002 rejected `os.Root` for opening input paths, because it follows symlinks within the root across intermediate components. Here it is pinned to a directory descriptor already verified symlink-free and is used only with single-component names, so there are no intermediate components. **Verified** in the Go 1.27.1 source: `Root.Link`, `Rename`, `Remove`, `Lstat` and `OpenFile` exist and use `linkat`/`renameat` on Unix. A by-path rename is not safe under a parent swap: the security review verified on macOS that it follows the swapped parent.

</Callout>

## Accepted risks

<Callout id="risks-callout" tone="risk">

- **Fatal signals.** SIGKILL, SIGINT, SIGTERM or a crash during the write can leave a hidden `.redactscan-*.tmp` file holding redacted bytes.
- **Power loss.** The directory fsync is best effort, so a rename just before power loss may be lost.
- **Ignore and sync rules.** The derived name may not match them (for example `.env` becomes `.env_cleaned`), and uncovered secret formats pass through to the file. The user accepted both; stderr always prints the note.
- **Shared directories.** In sticky, world-writable or group-writable directories another user can create the destination first, so no-clobber refuses (fail closed).
- **Replaced files.** Hard links to an old destination keep the old content. A replaced file is reset to 0600 and owned by the invoking user (root when run as root). Inherited ACLs can grant more access than 0600.
- **Filesystems without hard links.** No-clobber mode fails closed; `-force` works.
- **Platforms.** macOS and Linux only.

</Callout>
