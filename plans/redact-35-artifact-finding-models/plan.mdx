## Outcome

Every future detector, the redact pipeline, the policy engine and the report code share three types: `artifact.Artifact` (with `SourceMetadata`), `finding.Finding` and `finding.Severity`.

- Severity is an ordered integer whose zero value is invalid. `Compare` ranks invalid values highest, for sorting.
- `AtMost` and `AtLeast` are the threshold checks, and they fail closed when either side is invalid.
- `Finding.Validate()` rejects an unset severity, evidence over 256 bytes, non-UTF-8 evidence, and metadata that isn't a small set of bounded scalar values.
- `Artifact.Validate()` applies the same metadata check.
- Errors never echo content.

There is no I/O and no new dependency. Story: [REDACT-35](http://localhost:8080/issue/REDACT-35). Full spec: `docs/features/artifact-finding-models/spec.md`.

## Severity: sorting vs threshold checks

<Callout id="threshold-decision" tone="decision">

`Compare` is for sorting. Every invalid value ranks above `SeverityCritical`, and invalid values are equal to each other. It is **not** a threshold check: with an invalid or unset threshold `t`, `s.Compare(t) <= 0` is true for every valid `s`. Allow and deny decisions use `AtMost` (false if either side is invalid) and `AtLeast` (true if either side is invalid).

</Callout>

## Evidence and metadata: redacted or bounded

<Callout id="evidence-contract" tone="warning">

**Contract (package and field docs).**

- `ID`, `Category`, `Title`, `Description`, `Evidence` and `Metadata` values are constant text or redactor output, never raw scanned content or secrets.
- `Evidence` is at most 256 bytes and valid UTF-8. `Validate` rejects bad evidence and never truncates.
- `Validate` cannot detect secrets; the detector is responsible for redaction.
- Never format a `Finding` or `Artifact` with `%v`, `%+v`, `slog` or JSON into logs or errors. Log `ID` and `Severity.String()` only.

</Callout>

## Follow-ups (rules from the security design review)

- **Policy:**
  - Use `AtMost`/`AtLeast` or `Valid()` on both sides. Never compare raw ints.
  - Validate every threshold when config loads, and refuse to start if one is missing.
  - Call `Validate` on every finding; an invalid finding leads to block or error.
  - Never load policy from scanned content.
  - Record an ADR when severities become configuration.
- **Report / MCP:**
  - Call `Validate` on every finding and fail closed.
  - Escape C0, C1, ESC and bidi characters in `Evidence`, `Title`, `Description`, `File`, `RelativePath`, `Name` and `URI`.
  - Output only allowlisted metadata keys.
  - Never reflection-format findings into logs or errors.
- **Ingest:** reduce URI to scheme, host and path; add typed `Source.Type` constants; treat metadata as read-only once set; set `Path` only from locations `safefs` has checked.
- **Quarantine:** never use `RelativePath`, `Name` or `File` for filesystem operations; check `SHA256` before using it as a file name.
- **Detectors:** every `Evidence`, `Title`, `Description` and `Metadata` value is constant text or redactor output; security review checks each detector.
