title: "Live log source: FileSource follows a log safely, emits only complete lines, and fails closed on a suspicious rotation"
---

## Outcome

`internal/logs` adds the `LogSource` interface from architecture section 15 and its first adapter, `FileSource`. It follows a log file like `tail -F` and sends complete lines on a channel. Memory stays bounded, and a fragment of a line is never emitted. Truncation and rotation are handled by standard-library polling. Every reopen goes through `safefs.OpenRegular`, plus an owner check and a link-count check. Story: [REDACT-65](http://localhost:8080/issue/REDACT-65). Full spec: `docs/features/file-log-source/spec.md`.

Concrete example: `NewFileSource("app", "/var/log/app/app.log", FileOptions{})`, then `Read(ctx, Query{})`, streams each newly appended line. A 3 MiB JSON line becomes one marker `{Truncated: true, Dropped: 65537}` and none of its content. When logrotate rotates the file, the source finishes the old file up to its size at detection, then reopens the path. If the path is now `app.log -> ~/.ssh/id_ed25519`, the stream ends with one `Err: safefs.ErrSymlink` entry and the channel closes.

<Callout id="scope-callout" tone="info">

**Non-goals:** a CLI command; redaction inside the adapter (the adapter emits raw lines and redaction comes in a later story); MCP, a ring buffer or search; last-N lines or a no-follow mode; fsnotify or backoff; other adapters; globs or multiple files; Windows (`ErrUnsupportedPlatform`).

</Callout>

## Line rules

<Table
  id="lines-table"
  columns={["Case", "What is emitted", "Dropped"]}
  rows={[
    ["Complete line with at most MaxLineBytes bytes", "Line (fresh copy, trailing newline removed, carriage return kept)", "0"],
    ["Line crosses MaxLineBytes before its newline", "One marker at once; the rest is discarded silently", "bytes discarded so far (at least cap + 1)"],
    ["Start at end, file does not end in a newline", "Fragment skipped; one marker at the newline or the cap", "bytes skipped"],
    ["Partial line cut by truncation or rotation", "One marker (none if this line already had one)", "pending bytes"],
    ["Partial line at cancellation", "Nothing", "n/a"]
  ]}
/>

<Callout id="lines-decision" tone="decision">

**No fragment of a line ever leaves the adapter.** The threat model forbids splitting input across `Redact` calls, because a secret cut at the cap (for example an AWS key ID shortened below its 16-character minimum) would get past the detectors. `Dropped` is counted with a saturating add, but because the marker is sent once, when the cap is crossed, the value is bounded in practice. Newlines are found by scanning a fixed buffer by hand: no `bufio.Scanner`, `ReadBytes` or `ReadString`.

</Callout>

## Reopen checks

<Callout id="reopen-decision" tone="decision">

**On reopen, the owner uid must equal the first file's uid and the link count must be exactly 1. Otherwise the result is `ErrReopenRefused`.** This covers what `safefs` does not detect: a hard link to the user's own `~/.aws/credentials` planted at the path, or a file pre-created by another user in a shared log directory. A rotation that changes ownership, or a log with two hard links, ends the stream; that operational cost is intended. **Verified** with `go doc syscall.Stat_t` (go1.27.2): `Nlink` is `uint16` on darwin, `uint64` on linux/amd64 and `uint32` on linux/arm64 and linux/386, so it is converted to `uint64`; `Uid` is `uint32` everywhere. A `Sys()` that is not a `*syscall.Stat_t` is refused. The different-owner case is tested through an `fstat` seam, because a different owner cannot be created without root.

</Callout>

## Accepted risks

<Callout id="risks-callout" tone="risk">

- **Two rotations within one interval** skip the middle file. Writes to the old file after detection are lost, because the drain is bounded.
- **copytruncate followed by regrowth** past the offset within one interval: the truncation is missed, and a mid-line fragment can be emitted.
- **Inode identity** on NFS, FUSE and overlayfs can report a rotation falsely or miss one. A hung `Lstat` or read delays cancellation.
- **/proc and /sys files** (size 0) are re-emitted on every tick, so they are unsupported input.
- **First open** does not check the link count. This matches the safefs hard-link risk.
- **Cross-line secrets.** The guarantee is "no partial line"; a PEM block spans several entries.
- **A consumer that never cancels** pins one goroutine and one descriptor.

</Callout>

<Callout id="callers-callout" tone="warning">

**Caller constraints** (package doc and threat model): redact with context across lines; never expose `Line` outside the process (to MCP or logs) before redaction; escape CR, NUL, ANSI and bidi characters before display; cap concurrent `Read` calls (each costs one fd, one goroutine and up to `MaxLineBytes` + 32 KiB); always cancel `ctx`; never allocate based on `Dropped`.

</Callout>

## Verification

- `task test` after each step. `task verify` (fmt, lint, test, cross, security, secrets) before each PR is marked ready.
- Each PR runs `go test -race ./internal/logs/...` and the Linux container run `docker run --rm -v "$PWD":/src -w /src golang:1.27 go test ./...`, and records both results in the PR.
- Break-the-guard checks, each reverted afterwards: emit pending bytes on cut; remove the cap check; compare against the first Lstat instead of Fstat; drop the Nlink check; drop the owner check; make the drain unbounded; treat not-found at reopen as fatal; remove ctx.Done from the send select. Each change must make a test fail.
- Tests use real files only, apart from two noted seams (rotation timing and fstat). They wait on channel deadlines and use sentinel lines instead of sleeps.
- `staff-engineering-reviewer` and `security-reviewer` review each PR.
